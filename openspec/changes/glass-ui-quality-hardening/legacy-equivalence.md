# Legacy Equivalence Review

## Scope And Evidence

- Legacy revision: `f1c8ab7da` (`pre-glass`), not the already redesigned hardening baseline `c4efeec16`.
- Input: schema-v2 `/tmp/pre-glass-audit.json`, specifically the 31 `anchors.removedCandidates`, three API calls, one store call, and three links. The report is a discovery aid, not evidence that an absent string is a removed feature.
- Review method: inspect the old template and its production caller, then follow the current template event/prop into its handler, request, or generated identifier. Test references below identify assertions inspected; they do not imply those tests were rerun in this review.
- This document does not close all other action/model/visibility occurrences in the complete audit. In particular, it does not equate a handler name appearing somewhere in the repository with an operable UI action.

## Validation Limits

- This reviewer actually ran `BaseDialog.spec.ts`, common `StatCard.spec.ts`, `Button.spec.ts`, and `DataTable.spec.ts`: **4 files / 24 tests passed**. These support wrapper/sticky/basic table compatibility, not a universal preservation claim.
- The newly restored ProfileInfoCard test cases explicitly exercise all five values in simple and standard modes, refreshed user values, zero values, and malformed dates. Their execution is owned by `auth_forms` and the final verification record.
- Endpoint restoration, NotFound dashboard destination, and monitor refresh accessible-name restoration are visible in the working tree. Final execution evidence remains owned by their implementation agents; source presence is not labeled as an executed test.
- Existing proxy parser and group pricing helper tests are not browser evidence for submitting every form. The audit distinguishes source contract equivalence from unexecuted end-to-end tests.
- Full hardening acceptance also requires the Keys mobile information restoration identified during this review: cumulative actual cost is not quota usage, all enabled limit windows need amounts/reset details, and long IP/date values need readable presentation. See the implementation and browser evidence recorded by root.
