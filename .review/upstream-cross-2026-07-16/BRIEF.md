# 上游交叉 Review 共享规范

## 背景
- 本仓库: `personal-dev` @ HEAD
- 上游: `upstream/main` = Wei-Shaw/sub2api
- 对比基线: `git merge-base HEAD upstream/main` 到 `HEAD` 的三方差异视角
- 主要命令:
  - `git diff --stat upstream/main...HEAD -- <paths>`
  - `git diff upstream/main...HEAD -- <paths>`
  - `git log --oneline $(git merge-base HEAD upstream/main)..HEAD -- <paths>`
  - 必要时对照 `git show upstream/main:<path>` 与本地文件

## 角色
你是**独立模块审查官**。只读分析，**禁止**修改任何文件、禁止 commit/push、禁止安装依赖。

## 审查维度（每条发现都要覆盖可适用项）
1. **正确性**: 逻辑 bug、竞态、错误处理、协议状态机、部分失败
2. **安全**: 鉴权/授权、密钥泄漏、注入、SSRF、越权、审计绕过
3. **计费/一致性**: 双重计费、漏计费、余额/配额一致性、幂等、事务边界
4. **架构边界**: handler→service→repository；service 不得直接依赖 redis/gorm/repository 实现
5. **可维护性**: 与上游分叉成本、重复实现、难合并的热点
6. **可观测性/运维**: 日志噪声、失败归因、迁移安全性、回滚
7. **测试缺口**: 关键路径是否有单测/集成覆盖

## 发现分级
- **P0 阻断**: 资金/安全/数据损坏/生产可用性
- **P1 高**: 明确 bug 或高概率回归
- **P2 中**: 设计债、边界漏洞、可维护性风险
- **P3 低**: 风格、小优化、文档

## 输出格式（必须严格遵守，写入指定文件）
```markdown
# Module N: <名称>

## 范围摘要
- 对比基线 / 本模块变更规模
- 相对上游的主要能力差异（bullet）

## 关键路径图
（文字说明请求/数据流）

## 发现清单
### [P?] 简短标题
- **位置**: `path:line` 或文件范围
- **相对上游**: 本地新增 / 本地修改 / 上游已有但本地偏离
- **问题**: ...
- **影响**: ...
- **证据**: 关键代码片段或 diff 要点（精简）
- **建议**: 具体可执行修复方向
- **交叉关注**: 可能与哪些模块/agent 重叠

## 与上游合并风险
- 冲突热点文件
- 语义漂移点（同名不同义）

## 测试与验证缺口
- ...

## 模块结论
- 整体风险评级: Critical / High / Medium / Low
- 是否建议合入上游 / 继续分叉 / 先修再合
- Top 3 必须处理项
```

## 质量要求
- 深度优先，不写空话。每条发现必须有文件证据。
- 不要把「多了功能」当缺陷；评估其正确性与分叉成本。
- 若模块内变更极大，优先审查：安全边界、计费、协议兼容、幂等、并发、与上游接口契约。
- 忽略纯生成物噪音（除非迁移/wire 手改异常）。
- 中文撰写。
